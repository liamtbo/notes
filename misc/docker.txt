
docker file -> image -> container

No sudo commands
    in every new terminal run the following
    newgrp docker

list all docker images
    docker image ls

remove docker image
    docker image rm -f <image name>

create a container from an image and run until code is done
    # run code and close
        docker run ros:humble
    # keep open for interation
        docker run -it ros:humble

print running containers
    docker container ps

print all created containers, running or stopped
    docker container ps -a

start an already existing container
    docker container start -i <container name>

stop a running container
    in terminal on main OS
    docker container stop <container name>

docker cotnainer prune
    deletes all stopped containers
    doesn't touch running containers

open multiple terminals in a container
    open new terminal window on host OS
    docker exec -it <container name> /bin/bash

making permanent changes to an image
    make a new docker file based off the image

building an image from a docker file
    cd into dir with dockerfile
    docker image build -t <desired name> .

You have code on host os and you want docker container to start up around those files
    volumes 
        shared virtual drive you can't easily access outside docker, but can make it availbale to any container that need it
    bind mounts
        moutn dir of source code into the container, and now the files are there to be accessed
        ex
            on host os, cd into folder
            docker run -it -v $PWD/<abs source folder>:<abs path inside docker>
            if you create a file inside this folder in the container, it'll be difficult to access outside the container
